# 透中島

3D 島嶼養成 × 互動劇情的療癒系網頁遊戲。

名字來自台語的「透中晝」——中午那段太陽最高的時間。
每天點一下決定島上的天氣（約 5 秒），想探索的時候再走一趟 3 分鐘的故事。
不強制每日遊玩、不設標準答案、不進行心理診斷。

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # 劇情資料驗收 + 航線測試 + 後端 API 端對端
npm run build   # 先驗收再建置
npm run docs    # 由 JSON 產生劇本文件與流程圖
```

## 設計上的幾個決定

**內容與程式分離。** 劇本、島嶼、練習卡、任務文案全部是 JSON。新增第七篇故事＝
新增一份 JSON、三張卡、一座島，**不用改任何程式碼**。

**前後端共用同一套引擎。** `src/core/` 是純函式、無副作用、不依賴瀏覽器。
同一組選擇在手機上和在伺服器上得到同一條航線，這件事每次 CI 都會驗證。

**航線由固定規則判定，AI 不參與。** 每篇三條航線依 priority 評估，最後一條是保底，
所以任何遊玩組合都落在恰好一條航線上。

**AI 掛掉也不影響體驗。** 結算的前三段永遠是預先寫好的；AI 那一段是選配，
而且 18 條航線都有完整的固定文案備援。

**效能寫進程式而不是文件。** 不用貼圖、不用陰影、不用粒子、不用後製；
地形每島合併成一個幾何，道具用 InstancedMesh，沒有輸入就不排程 RAF，
故事畫面開啟時整個地圖停止渲染。

**紀錄要能帶走，但不能因此知道你是誰。** 保存代碼是端對端加密：整份存檔在瀏覽器裡
用 PBKDF2 + AES-GCM 加密完才上傳，伺服器只收得到密文，沒有帳號、沒有 email。
代價講在前面——密碼忘記就真的解不開。

**願望島不替公司講好話。** 公司回應一個主題島上才長樹，只是「收到了」就什麼都不長，
位子空著。回應內容由企業端維護，前端不會自己生成公司的答案。

**驗收是建置的前置條件。** `npm run build` 會先跑驗證，劇情資料有無效連結、
孤兒節點、或走不到的結局，就不會產生 `dist`，Netlify 也就不會部署。
