# 05｜情緒練習卡、AI 個人化回饋與安全規範

## 結算的五段順序

走完一篇故事之後的順序是固定的，不會因為任何條件而改變：

```
1. 固定劇情結局   ← 預先寫好
2. 航線解析       ← 預先寫好
3. 情緒練習卡     ← 預先寫好
4. AI 個人化回饋  ← 選配，要按按鈕並同意才產生；可以直接跳過
5. 島嶼探索成果   ← 由航線判定結果決定
```

前三段永遠看得到，就算 AI 服務掛掉、沒有網路、或玩家拒絕使用 AI，體驗都是完整的。

## 情緒練習卡

18 張，每條航線一張，資料在 `content/practice_cards.json`。

```jsonc
{
  "card_id": "pc_01_boundary",
  "route_id": "r_01_boundary",
  "title": "一句話的界線",
  "subtitle": "把「不行」換成「我可以到這裡」",
  "why": "你在故事裡已經做到了把時間說出口。這張卡是把那句話先寫好⋯⋯",
  "steps": ["想一個最近讓你為難的請求⋯⋯", "寫下這個句型⋯⋯", "唸一次給自己聽⋯⋯"],
  "duration_minutes": 2,
  "when_to_use": "下次收到訊息、還沒回覆之前的那三十秒。",
  "note": "重點在第二個空格⋯⋯"
}
```

設計原則：

- **兩分鐘內可以開始**，有動詞、有場景，不是抽象建議。
- **不是作業**。每張卡都寫著可以不做；拿到就收進長椅的收藏，不會過期、不會提醒。
- **保底航線也有好卡**。「記一筆帳」「停損點」「掛掉之後的九十秒」不是安慰獎，
  它們針對的是那條路真正的成本。
- 內容來自情緒調節與溝通的一般性原則，**不是治療**，檔案開頭有 `disclaimer` 寫明。

## AI 個人化回饋

### AI 做什麼、不做什麼

| 做 | 不做 |
|---|---|
| 根據這一次的選擇、結局、航線，提出**可能**的心聲 | 生成劇情、新增角色或對白 |
| 提供另一個觀點 | 修改或重新判定航線 |
| 給一個具體的小練習 | 評價選擇的對錯 |
| —— | 做任何心理評估、判斷或診斷 |
| —— | 比較玩家與他人、給分數或等級 |
| —— | 提供電話、網址或任何聯絡方式（求助資源一律由系統端提供） |

完整的 system prompt 在 `content/ai_feedback.json` 的 `system_prompt`。

### 輸入

Schema：[`schema/ai_feedback_request.schema.json`](../schema/ai_feedback_request.schema.json)

```jsonc
{
  "version": "1.0.0", "locale": "zh-TW",
  "story":  { "story_id": "...", "title": "...", "theme": "..." },
  "ending": { "ending_id": "...", "title": "...", "summary": "...", "tags": [...] },
  "route":  { "route_id": "...", "name": "...", "meaning": "..." },
  "choices": [{ "node_title": "...", "choice_text": "...", "consequence": "..." }],
  "clues":   [{ "title": "...", "text": "..." }],      // 避免與心聲線索重複
  "practice_card": { "card_id": "...", "title": "..." }, // 避免與練習卡重複
  "player_note": "玩家自願填寫的一段話",                  // 沒填就不帶這個欄位
  "consent": { "ai_feedback": true, "use_player_note": true }
}
```

**不送出的東西**（伺服器端以白名單剝除，不是靠呼叫端自律）：
每日心情打卡、每週心情溫度計分數與答案、島嶼名稱、裝置識別碼、帳號資訊、
以及任何不在上面 schema 裡的欄位。

### 輸出

Schema：[`schema/ai_feedback_response.schema.json`](../schema/ai_feedback_response.schema.json)

```jsonc
{
  "version": "1.0.0",
  "type": "feedback",                       // 或 "safety"
  "possible_inner_voice": ["...", "..."],   // 1–3 句，必須用推測語氣
  "another_view": "...",                    // 10–240 字
  "small_practice": { "title": "...", "steps": ["..."], "duration_minutes": 2 },
  "closing": "...",
  "meta": { "source": "ai", "model": "...", "generated_at": "..." }
}
```

`content/ai_feedback.json` 的 `examples` 有四則完整範例：
立界線航線、獨撐航線（含玩家自填內容）、調節航線，以及觸發安全流程的情況。

### 安全與隱私管線

```
請求
 ├─ 1. Schema 驗證          不合法 → 400
 ├─ 2. 隱私剝除             白名單欄位；未同意就移除 player_note
 ├─ 3. 安全前置過濾         命中風險關鍵字 → 直接回 safety，不呼叫模型
 ├─ 4. 呼叫模型             沒有 API key 或逾時 → 固定文案
 ├─ 5. 安全後置過濾         ↓ 任一不過 → 固定文案
 │     ・格式不符 schema
 │     ・出現診斷詞彙（憂鬱症、焦慮症、確診、就醫、治療⋯⋯）
 │     ・出現評價詞彙（你應該、你最好、正確的做法、比較健康的是⋯⋯）
 │     ・出現電話號碼、網址或任何聯絡方式
 │     ・心聲句缺少推測語氣（可能／也許／會不會／有一種版本／或許）
 └─ 6. 回傳
```

實作在 [`netlify/functions/ai-feedback.mjs`](../netlify/functions/ai-feedback.mjs)，
每一關都有對應的測試（`tools/route-cases.mjs` 的「AI 回饋服務」區塊）。

### 固定文案備援

`content/ai_feedback.json` 的 `fallback.by_route` 為**全部 18 條航線**各寫一份完整回饋
（可能的心聲、另一個角度、小練習、收尾），格式與 AI 版本完全相同。

觸發時機：沒有設定 `ANTHROPIC_API_KEY`、服務逾時、回應格式不符、任一安全過濾沒過、
超過用量上限、或玩家本機先掃到風險關鍵字。

玩家看到的畫面一樣，只在卡片底下多一行小字：「這次用的是預先寫好的版本」。
**沒有錯誤畫面，也不會因此少掉任何一段結算內容。**

### 用量限制

`per_session: 3`、`per_day: 20`。超過直接使用固定文案，不是錯誤。

## 心情溫度計與專業規範

### 本遊戲使用的量表：BSRS-5

心情溫度計用的是**衛生福利部推行的「簡式健康量表（BSRS-5）」官方版本**，
題目、計分與分級都照原樣實作，沒有改寫。資料在 `content/daily_weekly.json`
的 `weekly.instrument`，`instrument_id` 是 `bsrs5`。

回想期間：**最近一週以來（包含今天）**。

| 題號 | 題目 |
|---|---|
| b1 | 睡眠困難，譬如難以入睡、易醒或早醒 |
| b2 | 感覺緊張或不安 |
| b3 | 覺得容易苦惱或動怒 |
| b4 | 感覺憂鬱、心情低落 |
| b5 | 覺得比不上別人 |

量尺：0 不會／1 輕微／2 中等程度／3 嚴重／4 非常嚴重。總分 0–20。

| 總分 | 分級 | 官方建議 |
|---|---|---|
| 0–5 | 身心適應狀況良好 | 身心適應狀況良好。 |
| 6–9 | 輕度情緒困擾 | 建議找家人或朋友談談，抒發情緒，給予情緒支持。 |
| 10–14 | 中度情緒困擾 | 建議尋求心理諮商或接受專業諮詢。 |
| 15–20 | 重度情緒困擾 | 需高關懷，建議轉介精神科治療或接受專業輔導。 |

### 遊戲裡怎麼呈現

既然用的是正式量表，就必須守住它的使用規範，同時避免把遊戲變成篩檢工具：

- **不對玩家顯示分數**（`show_score_to_player: false`）。只顯示該級距的**顏色**與一段說明。
  分數會留在本機紀錄裡，但介面上從頭到尾不出現數字，避免有人追著分數玩。
- 官方的建議文字（上表右欄）原文保留在 `band.official`，另外寫一段較口語的
  `band.copy` 給玩家看。兩段都不是診斷。
- 每次作答前後都顯示 `instrument.disclaimer`：這不是醫療診斷，也不判斷你有沒有任何狀況。
- **紀念物與分數無關**，完成就拿到。不會因為分數「比較好」而給比較好的東西。
- 企業端只看得到各顏色的**人數比例**，而且一樣要過 k 匿名門檻（見 `docs/06`）。

> 正式對外使用前，請向主管機關或職護確認使用規範。這一句寫在
> `instrument.clinical_note` 裡，不要拿掉。

### 安全題與關懷流程

BSRS-5 的**附加題 b6「有自殺的想法」**，量尺與前五題相同：

- **不計入前 5 題總分**。
- 依官方規則，**本題 2 分以上**（`trigger_threshold: 2`）即建議轉介精神科——
  **不論總分多少**。所以總分 0 分但 b6 答 2 分，遊戲一樣直接打開燈塔的求助資源。
  這條規則有獨立的測試守著（`tools/api-cases.mjs`）。
- 不影響島嶼、紀念物或任何獎勵。
- 關懷內容與電話號碼固定寫在 `content/daily_weekly.json` 的 `safety`，不由 AI 生成。

### 關鍵字偵測

碼頭許願的自填欄位與 AI 回饋的 `player_note` 都會掃描風險關鍵字
（每日天氣打卡已改成一鍵、沒有自填欄位）：

- **在裝置端執行**，命中就直接顯示求助資源。
- 不會因此額外上傳任何資料，也不會替玩家貼上任何標籤。
- AI 服務端另有一道相同的前置過濾，命中就不呼叫模型。
