# 07｜測試與驗收規格

## 怎麼跑

```bash
npm install
npm test        # 劇情資料驗收 + 航線測試 + 後端 API 端對端
npm run dev     # 本機開發伺服器
npm run build   # 先跑驗收，通過才建置（驗收失敗 = 建置失敗 = 不會部署）
npm run docs    # 由 JSON 重新產生劇本文件與航線總表
```

CI 在 `.github/workflows/tou-tiong-island.yml`，每次 push 與 PR 都會跑 `npm test` 與建置。

## 一、劇情資料驗收（`tools/validate.mjs`）

零外部依賴（CI 不需要為了跑驗證而安裝套件）。檢查九件事：

| # | 檢查 | 為什麼 |
|---|---|---|
| 1 | 每篇故事符合 `schema/story.schema.json` | 欄位、型別、命名規則、長度上限 |
| 2 | `node_id` / `choice_id` / `ending_id` / `clue_id` / `route_id` 全域唯一 | 跨故事也不能撞 |
| 3 | 所有 `next_node_id`、`default_next_node_id`、`conditions` 指向存在的節點 | **無無效連結** |
| 4 | 每個節點都從 `start_node_id` 可達 | **無孤兒節點**（寫了卻走不到的內容） |
| 5 | 非結局節點一定有出口；結局節點對應 `endings[]` 的一筆 | 不會卡死 |
| 6 | **窮舉所有選擇組合**：每條路徑都走得到結局、都落在恰好一條航線 | 核心保證 |
| 7 | 每個結局、每條航線至少有一條路徑可達 | 沒有看不到的結局 |
| 8 | `state_effects` 與條件運算式只引用 `state_vars` 宣告過的變數 | 打錯字會被抓到 |
| 9 | 航線的 `practice_card_id`、`island_growth_id` 存在；反向也檢查沒有孤兒內容 | 資料不脫鉤 |

另外會重新產生 `content/story_index.json`，確保索引與劇本永遠同步。

## 二、航線與 AI 過濾（`tools/route-cases.mjs`）

### 黃金案例

窮舉六篇全部 **162 條路徑**，記錄「選擇序列 → 結局 → 航線」，比對
`tests/cases/route_cases.json`。任何劇本改動若影響了結局或航線的對應關係，
測試會立刻失敗並列出差異。

刻意調整時用 `node tools/route-cases.mjs --update` 重新產生，差異會出現在 git diff 裡供審閱。

### 設計意圖案例

18 條人寫的斷言，鎖住「這樣走應該得到這條航線」的設計決定，例如：

```js
{ why: '急停＋降載＋留紀錄 → 安全優先航線、結局「欄杆」',
  choices: ['c_03_d1_stop', 'c_03_d2_partial', 'c_03_d3_record'],
  route: 'r_03_safety', ending: 'e_03_railing' }
```

這一層抓到過兩個真實問題（見 `docs/04`），兩次修的都是規則，不是期望值。

### 航線涵蓋性

每篇故事的 27 條路徑必須覆蓋到全部三條航線，且每條路徑都有航線。

### AI 回饋服務

| 測試 | 驗證什麼 |
|---|---|
| 合法請求通過驗證 | 正常路徑 |
| 未同意 AI 回饋時被擋下 | 同意機制 |
| 缺少 route 時被擋下 | 必填欄位 |
| 未同意使用自填內容時 `player_note` 被剝除 | **隱私** |
| 白名單外的欄位一律丟掉 | **隱私**（心情、裝置 id 等不會外流） |
| 同意後 `player_note` 才送出 | 同意機制 |
| 正常回應通過後置過濾 | 不會誤殺 |
| 出現診斷詞彙會被擋下 | **安全** |
| 出現評價詞彙會被擋下 | **不評價選擇對錯** |
| 出現電話或網址會被擋下 | 求助資源只能由系統端提供 |
| 心聲缺少推測語氣會被擋下 | 不得斷言玩家的感受 |
| 18 條航線都有固定文案備援 | AI 掛掉時體驗完整 |
| 安全回應帶齊求助資源 | 關懷流程 |

## 三、後端 API 端對端（`tools/api-cases.mjs`）

直接呼叫 handler，不需要起伺服器。

**最重要的一條**：六篇各跑一條代表路徑，比對「本機引擎判定的航線」與
「後端 API 判定的航線」必須完全一致。兩邊共用 `src/core/`，這個測試在守住那件事。

其他涵蓋：內容端點、session 建立／恢復／選擇／推進／結算、島嶼解鎖與命名、
重走不重複解鎖但累計次數、每日打卡與驗證、溫度計計分與區間、安全題觸發關懷流程、
錯誤碼（404 / 400 / 409），以及團隊統計的 k 匿名門檻與無個人欄位。

## 四、瀏覽器實測

用 Playwright ＋ Chromium，在 390×844 與 1280×800 兩種視窗驗證：

- 場景正常初始化、無 JS 錯誤
- 七座島的名牌與四個互動點都在畫面內
- Draw calls 與三角形數在預算內（15／2,694 與 28／9,142）
- 點島 → 面板 → 出航 → 故事畫面開啟後 `scene._paused === true`
- 決策點正確顯示三個選項，選完出現心聲線索
