# 02｜3D 地圖、互動與手機效能規格

## 視覺方向

Low Poly 低多邊形 ＋ Isometric 等角視角 ＋ 六角形地塊 ＋ **奶油暖調**。
色票集中在 `src/world/palette.js`，3D 與介面共用同一組顏色，所以兩邊不會對不起來。

色調取自 V8 原型：紙白底、淡藍轉蜜桃的天空、暖砂島、鼠尾草綠、金色重點。
**刻意避開偏藍偏冷的粉彩**——療癒感來自暖色與低彩度，不是高明度。

- 平面著色（`flatShading: true`），刻意保留塊面感。
- **完全不使用貼圖**，所有顏色寫在頂點色裡。
- 海面是一塊**有限的圓盤**（大小隨群島算出來），不是無限平面。
  用無限平面會把天空整片擋掉，看不到漸層也看不到太陽——V8 原型的通透感就是這樣來的。
- 每座島一圈淺灘，沒有水面動畫、沒有折射、沒有反射。

### 天空、太陽與天氣：用 CSS 做，不用 draw call

天空漸層、太陽、天氣濛紗都是 canvas **底下**的 CSS 圖層
（`renderer` 開 `alpha: true`、`setClearAlpha(0)` 讓它透出來）。
它們不是 3D 物件，所以增加零個 draw call、零個三角形。

每日天氣打卡會同時改這幾件事（`sceneManager.setWeather()`）：

| | 晴 | 陰 | 雨 |
|---|---|---|---|
| 天空漸層 | 藍天轉蜜桃 | 灰白 | 鉛灰 |
| 太陽（CSS） | 有 | 無 | 無 |
| HemisphereLight 天空／地面色 | 暖黃／暖砂 | 冷灰／灰綠 | 青灰／灰 |
| DirectionalLight 強度 | 1.45 | 0.52 | 0.34 |
| 海水 | 青綠 | 灰青 | 深灰藍 |
| 雲朵數量／高度 | 2 朵、高 | 8 朵、壓低 | 10 朵、更低 |
| 雨絲 | 0 | 0 | 80 |
| 島民在做的事 | 除草、喝下午茶 | 同晴天 | 換雨衣、撐傘 |

**HemisphereLight 的天空／地面色是最有效的那根槓桿**。在沒有貼圖的平面著色場景裡，
只改方向光強度幾乎看不出差別——晴天和陰天會長得一模一樣。要讓三種天氣一眼分得出來，
得連環境光的色溫一起換。

所有顏色切換都是插值過去的（`_stepColours`），不會硬跳。

### 會動的東西

島是靜的沒關係，島上不能是死的。所有會動的東西都走 InstancedMesh ＋ 逐幀更新矩陣，
不額外增加 draw call：

| 東西 | 行為 |
|---|---|
| 島民 | `patrol` 來回走（走到底會轉身）、`sip` 喝東西、`breathe` 呼吸起伏、`fish` 釣魚、`circle` 盤旋 |
| 願望島的小船 | 浮在水面上下搖、左右晃，每艘相位不同 |
| 雲 | 橫向漂移，飄出範圍就繞回來 |
| 雨 | 落到水面以下就重新丟回天上 |
| 燈塔光束 | 點燈塔時淡入 0.4 秒、旋轉掃射、淡出 0.6 秒，同時把燈室打亮 |

島民**依天氣換造型與行為**：同一隻熊，晴天是 `animal_bear_mow` 在除草，
雨天換成 `animal_bear_rain` 穿雨衣整理花園。換的是模型與行為，不是多畫一次。

## 互動

| 操作 | 手機 | 電腦 |
|---|---|---|
| 旋轉群島 | 單指拖曳 | 滑鼠拖曳 |
| 縮放 | 雙指捏合 | 滾輪 |
| 選島 | 輕點島嶼或它的名牌 | 點擊 |
| 進入功能 | **直接點主島上的文字**（燈塔、碼頭、郵筒…） | 同左 |
| 切換視角 | 右上角「全覽／回島」 | 同左 |

- **島嶼與島上的文字是唯一的點擊互動物件**，沒有角色、沒有移動系統。
- 入口的文字一直看得到，不用先點圓點再點一次——少一次點擊就少一個放棄的理由。
- 點擊用 raycaster 對「隱形代理圓柱」判定（`material.visible = false`，不進渲染但可被射線擊中），
  不對地形或樹木做射線測試。
- 短按且位移小於 8px 才算點選，避免轉動鏡頭時誤觸。
- 島嶼名牌是 DOM 按鈕：比 3D 文字便宜、在小螢幕上清楚、而且螢幕閱讀器讀得到。
- **標籤定位是會點錯的地方，所以規則寫死**：主島的五個入口排成固定的一圈
  （角度寫死、半徑隨島的投影大小縮放、夾在 76–128px），位置可預測；
  島名後放，由近到遠依序擺，撞到就往上讓。跑出畫面的標籤直接藏起來
  （`opacity: 0; pointer-events: none`），**不硬擠回邊緣**——擠回來只會疊在一起點錯。

### 鏡頭

`src/world/cameraController.js` 自己實作，沒有用 OrbitControls：

- 只需要旋轉與縮放，自己寫比較小，也能精準控制觸控行為。
- **刻意不做阻尼**：阻尼會逼著每一幀都重繪，與按需渲染衝突。
- 仰角限制 22°–68°，避免轉到水平看見海平面邊緣或垂直俯視失去立體感。
- 進場停在 `focusHome()`：**把主島與願望島一起框住**。小船從碼頭開出去要看得到它停在哪裡，
  但又不能推太近，否則主島那一圈入口會被擠出畫面。鏡頭中心偏向主島（0.7）。
- 「全覽」用 `fitToWorld()`：把世界 AABB 的角點投到相機座標，直接解出剛好容得下的距離，
  而不是寫死數字——手機直向與桌機橫向需要的距離差很多。
- 直向螢幕（aspect < 0.78）自動把視野角度從 34° 放寬到 46°，否則鏡頭得退到很遠。
- 點主島與願望島**不會推近鏡頭**（它們本來就在預設視角裡）；點故事島才飛過去。
- 縮放範圍 9–140。拉到最近大約是一座島填滿畫面；再近就會看到低多邊形的稜角，
  那是美術的上限，不是效能的上限。

## 效能守則

這些不是口號，每一條都在 `src/world/sceneManager.js` 裡被執行：

| 項目 | 做法 |
|---|---|
| 即時陰影 | **關閉**（`renderer.shadowMap.enabled = false`） |
| 動態光源 | **沒有**。只有 1 盞 HemisphereLight ＋ 1 盞不投影的 DirectionalLight，位置固定 |
| 粒子特效 | **沒有** |
| 後製與模糊濾鏡 | **沒有**，不載入任何 EffectComposer |
| 貼圖 | **完全不用**，顏色走頂點色，記憶體與頻寬都省下來 |
| 材質數量 | 整個場景只有 2 個（地形、道具），海面另用最便宜的 MeshBasicMaterial |
| 地形 draw call | 每座島的所有六角地塊合併成 1 個 geometry |
| 道具 draw call | 同型別道具收成 1 個 InstancedMesh，不論島上長出幾百棵樹 |
| 淺灘 | 所有島的淺灘合併成 1 個 geometry |
| 天空・太陽・天氣濛紗 | CSS 圖層，**0 個 draw call** |
| 島民與小船 | 同造型收成 1 個 InstancedMesh，動畫只改矩陣 |
| 渲染策略 | **按需渲染**：沒有輸入、沒有狀態變化就不呼叫 render，連 RAF 都不排程 |
| 故事畫面 | 開啟時 `scene.pause()`，地圖完全停止渲染；關閉時 `resume()` |
| 像素比 | 依裝置分級設上限：低階手機 1.0 ／一般手機 1.5 ／桌機 2.0 |
| 抗鋸齒 | 手機關閉，桌機開啟 |
| 更新頻率 | 有動畫時低階手機 24fps、其他 36fps；靜止時按需渲染，多數時間是 0fps |
| 霧與遠裁切面 | 隨鏡頭距離調整，拉遠時遠處的島不會被整片霧吃掉 |

### 實測數字

用 Playwright ＋ Chromium 實測，390×844（iPhone 尺寸）與 1280×800：

| 場景 | Draw calls | Triangles | 貼圖 |
|---|---|---|---|
| 全新存檔（六島未解鎖） | 27 | 4,616 | 0 |
| 六島全開、18 條航線全部長出 | 40 | 12,064 | 0 |
| 同上，雨天（多 80 根雨絲、雲變多） | 41 | 13,740 | 0 |
| 同上，桌機 1280×800 | 40 | 12,064 | 0 |

預算上限設在 60 draw calls（`src/world/perf.js` 的 `BUDGET`），最滿的情況用掉三分之二。
執行中可以用 `window.__tti.scene.stats()` 查當下的數字。

**「細節多」不是 3D 網頁跑不動的原因。** 真正的成本是 draw call 數、貼圖記憶體、
即時陰影／後製，以及有沒有一直重繪——三角形數量反而最便宜。壓力測試裡額外塞進
5,000 個用 instancing 畫的裝飾物（＋40 萬個三角形），draw call 只增加 1，
每幀成本量不出差別。所以要加細節，規則只有兩條：

1. 同一種東西用 instancing 一次畫完。
2. 不要為了細節引進貼圖檔、即時陰影或粒子。

會踩到上限的是「每個物件都長得不一樣」——一百種不同的小物件就是一百個 draw call。

## 地圖內容由資料產生

整個 3D 場景從 `content/island_map.json` 生成，程式裡沒有寫死任何一座島：

```jsonc
{
  "hex": { "size": 1.0, "orientation": "flat-top", "level_height": 0.42, "base_depth": 0.55 },
  "home": { "hexes": [...], "landmarks": [...], "interactions": [...], "animals": [...] },
  "wish_island": {                          // 碼頭許願的另一半
    "hexes": [...], "landmarks": [...],
    "dock_slots": [...],                    // 小船停靠位，放幾艘就佔幾個
    "tree_slots": [...]                     // 每個主題一個位子，照公司回應長樹
  },
  "islands": [{
    "island_id": "island_boundary",
    "origin": { "q": -5, "r": 2 },        // 軸向座標，加到各 hex 之上
    "base":   { "hexes": [...], "landmarks": [...] },
    "growth": [{ "growth_id": "...", "route_id": "...", "hexes": [...], "landmarks": [...] }]
  }],
  "flora_table": { ... },                  // 各島的樹種
  "flora_density": { ... }                 // 每種植被的密度
}
```

- 座標是 flat-top 軸向座標：`x = size × 1.5 × q`、`z = size × √3 × (r + q/2)`。
- 草木不寫在資料裡，由 `islandBuilder.js` 以「島嶼 id ＋ 已解鎖航線數」為種子的亂數散佈，
  所以同一座島每次重建長出來的位置都一樣，但資料檔不用塞幾百筆座標。
- 新增一座島＝在 `islands[]` 多一筆，不用改任何程式。

## 可及性

- 名牌與互動點是真的 `<button>`，可用鍵盤聚焦、有 `aria-label`。
- 尊重 `prefers-reduced-motion`：關閉所有進場動畫與標籤過場。
- 文字與背景對比度依循 WCAG AA；選項按鈕最小觸控區域 44×44。
- WebGL 無法初始化時顯示明確的說明，而不是白畫面。
