# 02｜3D 地圖、互動與手機效能規格

## 視覺方向

Low Poly 低多邊形 ＋ Isometric 等角視角 ＋ 六角形地塊 ＋ 溫暖柔和的粉彩色系。
色票集中在 `src/world/palette.js`，3D 與介面共用同一組顏色。

- 平面著色（`flatShading: true`），刻意保留塊面感。
- **完全不使用貼圖**，所有顏色寫在頂點色裡。
- 海面是單一平面 ＋ 每座島一圈淺灘，沒有水面動畫、沒有折射、沒有反射。

## 互動

| 操作 | 手機 | 電腦 |
|---|---|---|
| 旋轉群島 | 單指拖曳 | 滑鼠拖曳 |
| 縮放 | 雙指捏合 | 滾輪 |
| 選島 | 輕點島嶼或它的名牌 | 點擊 |
| 重設視角 | 右上角「視角」 | 同左 |

- **島嶼是唯一的點擊互動物件**，沒有角色、沒有移動系統。
- 點擊用 raycaster 對「隱形代理圓柱」判定（`material.visible = false`，不進渲染但可被射線擊中），
  不對地形或樹木做射線測試。
- 短按且位移小於 8px 才算點選，避免轉動鏡頭時誤觸。
- 島嶼名牌是 DOM 按鈕：比 3D 文字便宜、在小螢幕上清楚、而且螢幕閱讀器讀得到。

### 鏡頭

`src/world/cameraController.js` 自己實作，沒有用 OrbitControls：

- 只需要旋轉與縮放，自己寫比較小，也能精準控制觸控行為。
- **刻意不做阻尼**：阻尼會逼著每一幀都重繪，與按需渲染衝突。
- 仰角限制 22°–68°，避免轉到水平看見海平面邊緣或垂直俯視失去立體感。
- 進場會把整座群島框進畫面（`fitToWorld()`）：把世界 AABB 的角點投到相機座標，
  直接解出剛好容得下的距離，而不是寫死數字——手機直向與桌機橫向需要的距離差很多。
- 直向螢幕（aspect < 0.78）自動把視野角度從 34° 放寬到 46°，否則鏡頭得退到很遠。

## 效能守則

這些不是口號，每一條都在 `src/world/sceneManager.js` 裡被執行：

| 項目 | 做法 |
|---|---|
| 即時陰影 | **關閉**（`renderer.shadowMap.enabled = false`） |
| 動態光源 | **沒有**。只有 1 盞 HemisphereLight ＋ 1 盞不投影的 DirectionalLight，位置固定 |
| 粒子特效 | **沒有** |
| 後製與模糊濾鏡 | **沒有**，不載入任何 EffectComposer |
| 貼圖 | **完全不用**，顏色走頂點色，記憶體與頻寬都省下來 |
| 材質數量 | 整個場景只有 2 個（地形、道具），海面另用最便宜的 MeshBasicMaterial |
| 地形 draw call | 每座島的所有六角地塊合併成 1 個 geometry |
| 道具 draw call | 同型別道具收成 1 個 InstancedMesh，不論島上長出幾百棵樹 |
| 淺灘 | 所有島的淺灘合併成 1 個 geometry |
| 渲染策略 | **按需渲染**：沒有輸入、沒有狀態變化就不呼叫 render，連 RAF 都不排程 |
| 故事畫面 | 開啟時 `scene.pause()`，地圖完全停止渲染；關閉時 `resume()` |
| 像素比 | 依裝置分級設上限：低階手機 1.0 ／一般手機 1.5 ／桌機 2.0 |
| 抗鋸齒 | 手機關閉，桌機開啟 |
| 更新頻率 | 低階手機上限 30fps，其他 60fps（按需渲染之下多數時間是 0fps） |
| 霧與遠裁切面 | 隨鏡頭距離調整，拉遠時遠處的島不會被整片霧吃掉 |

## 地圖內容由資料產生

整個 3D 場景從 `content/island_map.json` 生成，程式裡沒有寫死任何一座島：

```jsonc
{
  "hex": { "size": 1.0, "orientation": "flat-top", "level_height": 0.42, "base_depth": 0.55 },
  "home": { "hexes": [...], "landmarks": [...], "interactions": [...] },
  "islands": [{
    "island_id": "island_boundary",
    "origin": { "q": -5, "r": 2 },        // 軸向座標，加到各 hex 之上
    "base":   { "hexes": [...], "landmarks": [...] },
    "growth": [{ "growth_id": "...", "route_id": "...", "hexes": [...], "landmarks": [...] }]
  }],
  "flora_table": { ... },                  // 各島的樹種
  "flora_density": { ... }                 // 每種植被的密度
}
```

- 座標是 flat-top 軸向座標：`x = size × 1.5 × q`、`z = size × √3 × (r + q/2)`。
- 草木不寫在資料裡，由 `islandBuilder.js` 以「島嶼 id ＋ 已解鎖航線數」為種子的亂數散佈，
  所以同一座島每次重建長出來的位置都一樣，但資料檔不用塞幾百筆座標。
- 新增一座島＝在 `islands[]` 多一筆，不用改任何程式。

## 可及性

- 名牌與互動點是真的 `<button>`，可用鍵盤聚焦、有 `aria-label`。
- 尊重 `prefers-reduced-motion`：關閉所有進場動畫與標籤過場。
- 文字與背景對比度依循 WCAG AA；選項按鈕最小觸控區域 44×44。
- WebGL 無法初始化時顯示明確的說明，而不是白畫面。
